- Finding (user-observed): with `NSEvent.addGlobalMonitorForEvents` the app needed BOTH Input
  Monitoring and Accessibility. My earlier "Input Monitoring alone should work" was wrong.
- Decision: switched to a `.listenOnly` CGEventTap (`startInputMonitor`/`installTap` in AppDelegate.swift)
  to drop the Accessibility requirement. Reverses the earlier NSEvent-over-CGEventTap choice.
- Tap callback re-enables on `tapDisabledByTimeout/UserInput`; install retries every 2 s until the
  permission exists. Menu status line now reads "Typing: listening ✓" or the blocked warning.
- UNVERIFIED: that typing works with Accessibility OFF. Test: turn Accessibility off for
  Cat Partner Overlay, relaunch, type.

## Resolved: typing works with Input Monitoring only
- Symptom: menu said "listening" but only clicks on the cat registered. Cause: macOS had a stale
  Input Monitoring entry that did not match the current ad-hoc-signed build. Without an effective
  grant a session tap is created but delivers only the app's own events (clicks on the cat).
- My status line was misleading (it only checked that the tap existed). Now it also checks
  `CGPreflightListenEventAccess()`: "listening ✓" / "Clicks only" / "Not listening".
- Fix: `tccutil reset ListenEvent com.kent.catpartneroverlay`, delete leftover row in Input
  Monitoring, relaunch via `open`, grant again. Confirmed working by user.
- Gotcha: every rebuild changes the ad-hoc signature and can invalidate the grant. Repeat the reset.
  Permanent fix (not done): stable self-signed code-signing cert. Needs keychain changes; ask first.
- Gotcha: run via `open dist/CatPartnerOverlay.app`; running the inner binary from a terminal makes
  the terminal the responsible process for permissions.
- Confirmed by user: the app does not appear in Accessibility at all and typing works. Input Monitoring is the only permission it holds.

## Update: dragging fixed
- Symptom: cat could not be moved. Cause: `NSImageView` consumes mouse-down, so
  `isMovableByWindowBackground` never saw it. Fix: custom `CatView` (CatView.swift) draws the
  frame and moves the window itself in mouseDown/mouseDragged using screen coordinates;
  `acceptsFirstMouse` true so the first click drags (non-activating panel). Position persistence
  (didMoveNotification) is unchanged. UNVERIFIED until user tests drag + relaunch position.
- Rebuild changed the ad-hoc signature, so the Input Monitoring grant may need the tccutil reset again.

## Feature: key counter on the table (branch feature/key-counter)
- Count is drawn on the brown table in the sprite (CatView.drawCounter; table rect hardcoded as fractions of the
  Text is "Boops: N", centered in the lower body of the table (below the lip line).
  256px sprite, so custom sprites with a table elsewhere will misplace it).
- Every non-repeat keyDown = +1; Backspace (keycode 51) = -1, clamped at 0; held Backspace keeps decrementing,
  held other keys count once. Mouse clicks don't count. Forward-delete (fn+delete) counts as +1.
- Why net count: Backspace -1 means the number approximates characters currently typed, per the request.
- Privacy: the tap now reads the keycode, but only compares it to Backspace; nothing is stored or logged.
- Not persisted: resets on launch or via menu "Reset Counter". Open question: persist across launches / daily reset?
