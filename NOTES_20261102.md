## Update: .app packaging (same day)
- Added `scripts/build_app.sh` -> `dist/CatPartnerOverlay.app`, bundle id `com.kent.catpartneroverlay`,
  `LSUIElement` (no Dock icon), ad-hoc signed. Why: permission attaches to the launching app; under
  `swift run` that was the terminal (WezTerm), so every program run from it inherited key access.
- Removed the automatic Accessibility prompt (least privilege). Only Input Monitoring is requested.
  Unverified whether Input Monitoring alone suffices on this macOS (26); if keys fail, add Accessibility.
- Sprites now load: user folder -> `Contents/Resources/sprites` -> SwiftPM bundle (dev only).
- Gotcha: ad-hoc signature changes per build, so TCC may re-prompt after rebuilds.
- Position is now stored under the bundle id domain, so the saved position resets once.

## Update: NSEvent monitor -> listen-only CGEventTap
- Finding (user-observed): with `NSEvent.addGlobalMonitorForEvents` the app needed BOTH Input
  Monitoring and Accessibility. My earlier "Input Monitoring alone should work" was wrong.
- Decision: switched to a `.listenOnly` CGEventTap (`startInputMonitor`/`installTap` in AppDelegate.swift)
  to drop the Accessibility requirement. Reverses the earlier NSEvent-over-CGEventTap choice.
- Tap callback re-enables on `tapDisabledByTimeout/UserInput`; install retries every 2 s until the
  permission exists. Menu status line now reads "Typing: listening ✓" or the blocked warning.
- UNVERIFIED: that typing works with Accessibility OFF. Test: turn Accessibility off for
  Cat Partner Overlay, relaunch, type.
